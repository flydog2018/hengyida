## 0. 原始需求复述

恒易搭是一款面向企业的**原创零代码信息化系统搭建平台**：无编程基础的业务人员通过拖拽控件即可搭建业务系统；同一套代码通过配置切换，支持 SaaS 运营与客户私有化部署；一次搭建自动适配 PC 与手机端。核心硬性约束为**完全原创**（交互、视觉、数据模型、表单引擎、流程引擎、权限模型均自主设计，不模仿简道云/明道云/氚云/宜搭/轻流等，不基于开源低代码框架二次修改），并严格执行既定的 `hengyida/` 目录结构以保证可维护性与知识产权可溯源。

## 1. 产品目标与成功指标

### 1.1 产品目标（三个正交目标）

1. **零门槛搭建**：让无编程基础的企业业务人员，独立完成从建表、建页面到发布上线的全过程，不依赖外部开发。
2. **一套代码、双模交付**：SaaS 与私有化部署功能完全一致，仅通过配置切换运行模式与数据归属。
3. **原创可控、持续演进**：全栈自主设计，架构解耦、目录清晰、可溯源，未来不被第三方框架或开源低代码平台绑定。

### 1.2 可量化成功指标（MVP 验收基线）

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 首次搭建成功时间（TTFV） | ≤ 30 分钟 | 新用户无培训，完成「建应用 → 拖 3 个字段 → 发布 → 录入 1 条数据」 |
| 表单发布生效时间 | ≤ 10 秒 | 点击发布到 runtime 可录入数据 |
| runtime 首屏加载 | < 2 秒（P95） | 常规网络、常规表单规模 |
| 设计器拖拽流畅度 | ≥ 50 FPS，无可见卡顿 | 拖拽、缩放、属性变更场景 |
| 配置 JSON 导入/导出成功率 | 100% | 导出后可完整还原，支持版本回退 |
| 真实场景验证 | ≥ 3 个 | Phase 1 结束前支撑人事/客户/项目等 ≥3 类业务场景落地 |
| 动态建表自动化 | 100% | 表单发布自动生成数据表，零手工 DDL |

## 2. 用户画像与用户故事

### 2.1 用户画像

| 画像 | 特征与诉求 |
| --- | --- |
| 企业管理者 | 关注上线速度、数据自主可控、总体成本；决策是否采用 SaaS 或私有化 |
| 业务人员 | 无代码基础，关注「能不能自己搞定」，要求操作直观、即时见效 |
| 行政人事 | 高频搭建考勤、台账、请假、员工信息等表单，重视 Excel 导入导出 |
| 运营人员 | 关注数据筛选/排序、报表数据准确性与流程跟踪 |
| 系统管理员 | 负责角色与权限配置、部署运维、数据备份迁移 |

### 2.2 用户故事（含验收要点）

| 编号 | 用户故事 | 验收要点 |
| --- | --- | --- |
| US-01 | 作为业务人员，我想创建多个独立应用（如人事管理、客户管理），以便分业务管理 | 可新建/重命名/删除应用；单账号下应用列表清晰；每个应用可包含多个表单与页面 |
| US-02 | 作为无代码基础的用户，我想从控件库拖拽字段到画布，以便像搭积木一样做表单 | 文本/数字/日期/下拉/附件等基础控件可拖拽、排序、删除；操作即时预览 |
| US-03 | 作为搭建者，我想配置字段的标题、默认值、必填、校验与显示条件，以便收集规范数据 | 属性面板可编辑全部属性；必填与校验在 runtime 端生效；显示条件按其他字段值动态显隐 |
| US-04 | 作为搭建者，我想使用子表（一对多）与关联表（多对一），以便描述真实业务关系 | 子表可在主记录内增删行；关联表可选择目标表单记录并显示；配置 JSON 可正确表达两种关系 |
| US-05 | 作为财务/业务人员，我想配置公式字段（如金额=单价×数量），以便自动计算 | 支持四则运算与字段引用；runtime 实时计算；发布后数据落库正确 |
| US-06 | 作为搭建者，我想一键发布表单，以便立即使用 | 发布后 runtime 自动渲染页面并自动建表；发布失败给出明确原因；可重复发布 |
| US-07 | 作为使用者，我想在数据库表中筛选、排序、分页并导入导出 Excel，以便高效处理数据 | 列表支持条件筛选与多字段排序；分页稳定；Excel 导入有模板与错误提示，导出字段完整 |
| US-08 | 作为管理员，我想分配管理员/编辑者/查看者角色及应用级/表单级/行级权限，以便数据安全 | 三种角色权限边界清晰；三级权限可组合生效；越权访问被拒绝且不泄露数据 |
| US-09 | 作为管理员，我想导入/导出应用配置 JSON，以便备份与迁移 | 导出为可读 JSON；导入后页面、字段、关系、权限完整还原；环境间可迁移 |
| US-10 | 作为移动端用户，我想用手机访问同一应用，以便随时随地填报 | PC 配置一次，H5 自动适配布局并触控友好；数据两端一致（小程序方案锁定 Phase 2，不在一期） |

## 4. MVP 范围界定（Phase 1 / 织蜂·一期）

### 4.1 Phase 1 做什么（In Scope）

- **应用管理**：多应用、表单/页面组织、配置 JSON 导入导出。
- **表单设计器**：拖拽字段、字段属性/校验/显示条件、子表、关联表、公式字段、一键发布。
- **数据管理**：发布即自动建表、数据列表（筛选/排序/分页）、Excel 导入导出、数据行级权限。
- **权限系统**：三类角色 + 应用级/表单级/行级权限（不含第三方通讯录同步）。
- **多端**：PC 完整功能、H5 触控优化自适应。
- **技术底座**：统一 JSON Schema；designer 与 runtime 分离并共享控件定义；server/core 引擎与业务解耦；至少一种数据库的动态表结构实现；全功能 API 化；Docker 基础容器化。
- **品牌视觉基线**：落地已定稿的《恒信 VI 视觉识别系统手册》V1.1——单一深蓝色系（基石深蓝 #1B3D73 主色、浅雾蓝 #E8EFF8 背景、中灰 #9AA4B2 辅助），原创 H·X 蜜蜂标志，思源黑体字体族；严禁橙色/渐变/阴影。
- **非功能基线**：性能、可维护性、兼容性指标纳入验收。

### 4.2 Phase 1 不做什么（Out of Scope）

- 流程引擎（条件分支、会签、转交、审批流）——Phase 2，用户已确认不提前。
- 微信小程序正式发布——Phase 2，用户已确认不进一期；一期以 H5 覆盖移动访问。
- 企业微信/钉钉/飞书通讯录对接——Phase 2+。
- SaaS 计费、租户管理、K8s 集群、私有化一键部署包——Phase 3。
- 控件插件市场、开放 API 平台、模板市场——Phase 4。
- 多数据库同时支持——Phase 1 锁定 MySQL 8.0 先行，架构预留切换能力。
- 任何对现有低代码产品的界面/交互模仿，或基于开源低代码框架的二次修改——**全程禁止**。

### 4.3 锁定后的范围策略（v1.1 新增）

按 3 个月（12 周 + 2 周缓冲）、单人小团队并行基准，一期拆分为两个波次：先保核心闭环，再补增强项。

**波次 1 · 核心闭环（必须完成）**

- **应用管理**：多应用、表单/页面组织、配置 JSON 导入导出。
- **表单设计器**：拖拽字段、基础控件集、字段属性/校验/显示条件、子表、关联表、公式字段（四则运算）。
- **发布与数据**：一键发布 + 动态建表（MySQL 8.0）、数据列表（筛选/排序/分页）。
- **权限**：三类角色 + 应用级/表单级权限。
- **多端**：PC 端完整功能 + 基础 H5 适配。
- **技术底座**：统一 JSON Schema；designer 与 runtime 分离并共享控件定义；server/core 引擎与业务解耦；全功能 API 化；严格执行既定目录结构。

**波次 2 · 增强项（视投入在 Phase 1 末或 Phase 2 初完成）**

- Excel 导入/导出。
- 数据行级权限细化。
- H5 触控深度优化。
- 性能与非功能验收（拖拽 ≥50FPS、加载 <2s、注释率 >30%、关键模块 README、浏览器兼容）。
- Docker 基础容器化（本地可运行基座，SaaS 底座预留）。
- 原创性留痕（设计稿/原型/代码结构原始文档归档）。

**明确不在一期**：微信小程序、流程引擎、K8s 集群、SaaS 计费与租户管理、私有化一键部署包、控件插件市场 / API 开放平台 / 模板市场。

## 5. UI / 交互设计要点（原创性约束下）

### 5.1 原创性红线

- 不参考简道云/明道云/氚云/宜搭/轻流的信息架构、操作路径、控件面板布局与视觉风格；设计前须做「原创性自查」并记录。
- 交互、视觉、底层模型均自主设计；所有设计稿、原型、代码结构保留原始文档，确保知识产权可溯源。

### 5.2 设计原则

1. **搭建路径线性化**：以「选材 → 布置 → 设定 → 发布」为唯一主线，减少弹窗嵌套与深层菜单；每一步都有明确反馈。
2. **所见即所得**：画布即最终形态，属性修改实时反映；PC 与 H5 提供切换预览。
3. **一致的控件契约**：designer 的属性面板与 runtime 的渲染控件共用同一份控件定义与 JSON Schema，避免"设计一套、显示另一套"。
4. **克制的企业视觉**：简洁专业、留白充足、层级清晰；严格遵循已定稿 VI 手册——单一深蓝色系，基石深蓝 #1B3D73 标题/主视觉、浅雾蓝 #E8EFF8 背景卡片、墨黑 #1A1A1A 正文、中灰 #9AA4B2 辅助；Logo 使用 VI 标准 H·X 蜜蜂标志（原创建筑咨询行业意形，非「搭积木」占位概念）；字体思源黑体 Source Han Sans SC（SIL OFL 1.1 免费商用），英文 Source Sans 3；微软雅黑仅作系统兜底。禁止橙色、渐变、阴影、拉伸标志。
5. **容错与可恢复**：删除、覆盖、发布等关键操作可撤销或有确认；导入失败给出定位信息。
6. **移动优先的响应式**：H5 不是简单缩放，而是触控区域、单列布局与输入方式的重新适配。

### 5.3 建议信息骨架（供架构师/设计参考，非照搬现有产品）

- 设计器：左侧「控件与字段库」→ 中部「画布 + PC/H5 预览切换」→ 右侧「字段属性面板」→ 顶部「应用/表单切换 + 发布」。
- 使用端（runtime）：左侧「应用与表单导航」→ 主区「数据列表 / 表单填报」→ 顶部「角色与数据范围提示」。
- 管理端：应用列表、角色权限、配置导入导出为独立入口，不与搭建画布混杂。

## 7. 里程碑（锁定版）

| 阶段 | 目标 | 周期（锁定） | 关键交付 |
| --- | --- | --- | --- |
| Phase 1 · 织蜂一期 | 核心搭建引擎 + 表单设计器 + 数据管理 + 基础权限 + PC/基础 H5（核心波次 + 增强波次） | **3 个月（12 周 + 2 周缓冲）** | 可运行 MVP；核心闭环打通；≥3 个真实场景验证；目录规范、JSON Schema、API 化落地 |
| Phase 2 · 织蜂二期 | 流程引擎 + 权限增强（含行级细化）+ 多端适配（含小程序） | 1–2 个月 | 审批流可用；三端访问一致；第三方通讯录对接评估 |
| Phase 3 · 织蜂三期 | SaaS 运营平台（计费/租户）+ K8s 集群 + 私有化部署包 | 1–2 个月 | K8s SaaS 环境；Docker Compose 私有化一键交付 |
| Phase 4 · 织蜂持续 | API 开放、第三方集成、模板市场 | 持续 | 插件化控件与生态扩展 |

> **锁定口径**：以「单人小团队」并行方案为基准排期。若为**严格 1 人投入**，一期需裁剪至约 **45–65 人日**的核心范围，且仍有 **3–4 个月**延期的风险，须在排期评审时明确取舍。
